## 🕵️ MODUL 0.8: THE RUTHLESS DEEP-DEBUG & BUG-HUNTER AGENT
Agen AI wajib menjalankan peran sebagai **QA Auditor Ekstrem** untuk menemukan bug tak kasat mata yang sering lolos dari pengawasan manusia paling teliti sekalipun:

1. **Simulasi Concurrency & Race Condition:**
   * Pengujian klik ganda (*double-click* cepat < 50ms pada tombol checkout): Memastikan transaksi tidak tercatat dobel dan stok tidak berkurang dua kali (idempotency test).
2. **Audit Presisi Matematika Uang (Anti Floating-Point Trap):**
   * Dilarang keras menggunakan tipe `float` untuk nominal Rupiah (karena kelemahan binary float komputer: `0.1 + 0.2 = 0.30000000000000004`).
   * Seluruh kalkulasi uang WAJIB menggunakan **Integer bulat (sen/rupiah murni)** atau pustaka `Decimal` berpresisi tinggi.
3. **Boundary & Malicious Input Fuzzing:**
   * Uji coba input ekstrem: Nama pelanggan sepanjang 5.000 karakter, nominal minus (`-Rp 50.000`), karakter XSS (`<script>alert(1)</script>`), emoji UTF-8 4-byte, dan string kosong berspasi.
4. **Deteksi Memory Leak & Zombie Listeners:**
   * Memastikan setiap listener keyboard, interval timer, dan koneksi WebSocket/SSE di-cleanup saat komponen ditutup (*unmount*), sehingga aplikasi tidak semakin lambat jika dibuka seharian penuh di PC kasir.
5. **Database Execution Plan Stress-Test (`EXPLAIN ANALYZE`):**
   * Setiap query pencarian diuji secara virtual dengan estimasi 3.000.000 baris data untuk memastikan tidak ada *Sequential Scan* yang lolos tanpa index B-Tree.
6. **Timezone Edge Cases:**
   * Pengujian pergantian hari jam 00:00 WIB (memastikan rekap penjualan harian tidak terpotong atau tercampur dengan hari kemarin karena perbedaan UTC vs GMT+7).

## 🚀 MODUL 2: MOTION DESIGN & MICRO-INTERACTIONS (60 FPS LOCKED)

### 2.1 Kontrak 5 State Komponen Interaktif
Setiap elemen yang dapat diklik (Button, Card clickable, List item) wajib mendefinisikan 5 state:
1. `Default`: Tampilan normal dengan border dan hierarki jelas.
2. `Hover`: Perubahan brightness atau tone halus (150ms `ease-out`).
3. `Active / Pressed`: Efek tekan fisik nyata (`active:scale-[0.98]` atau `active:translate-y-[1px]`).
4. `Focus-Visible`: Ring fokus kontras untuk navigasi keyboard (`focus-visible:ring-2 focus-visible:ring-offset-2`).
5. `Disabled`: `opacity-50`, `cursor-not-allowed`, dan event klik dinonaktifkan.

### 2.2 Akselerasi GPU Mutlak (Zero Layout Reflow)
* ✅ **Hanya Animasikan Properti GPU:** `transform` (scale, translate, rotate) dan `opacity`.
* ❌ **DILARANG KERAS** menganimasikan properti layout: `width`, `height`, `top`, `left`, `margin`, `padding`. Pelanggaran ini memicu reflow browser yang membuat animasi lag/patah-patah.

### 2.3 Instant Feedback Loop
* Setiap aksi pengguna (klik simpan, hapus, print, submit) wajib menampilkan feedback visual instan (< 100ms):
  * Tombol berubah menampilkan loading spinner halus.
  * Toast notification muncul di sudut layar.
  * Terapkan Optimistic UI jika memungkinkan (update tampilan sebelum respons server selesai).

### 2.4 Standar Animasi & Component Registry (Magic UI & shadcn/ui)
* **Pola Copy-Paste Registry Mandiri:** Dilarang menginstal library animasi monolitik yang berat. Wajib menggunakan pola registry mandiri dari **Magic UI (`magicui.design`)** dipadu dengan **shadcn/ui**:
  * Komponen animasi disalin langsung ke folder `components/ui/` (micro-modular, rata-rata 50–120 baris per file).
  * Komponen rekomendasi utama:
    * `Number Ticker`: Untuk kalkulasi angka omset, stok sisa, dan metrik dashboard yang bertambah halus.
    * `Border Beam`: Indikator visual kartu aktif / proses cetak struk dan antrean berjalan.
    * `Animated List`: Transisi item keranjang belanja kasir masuk/keluar dengan spring physics alami.
    * `Ripple / Shimmer`: Umpan balik fisik instan pada tombol kasir dan tombol aksi utama.
* **Aturan Anti-Sirkus (Purposeful Motion):** Dilarang memasang animasi untuk dekorasi berlebihan yang norak (dilarang menumpuk meteor/partikel/shimmer secara bersamaan). Animasi HANYA boleh dipasang untuk memperjelas perubahan status data atau memberi feedback aksi nyata pengguna.

## 🏗️ MODUL 3: ARSITEKTUR FRONTEND & STATE MANAGEMENT

### 3.1 Feature-Driven Colocation
Struktur folder wajib berbasis fitur bisnis, bukan mengelompokkan semua file berdasarkan jenis teknisnya:
```text
src/
├── features/
│   ├── [nama-fitur]/          # Contoh: menu, checkout, auth, recorder
│   │   ├── components/        # Komponen UI spesifik fitur ini
│   │   ├── hooks/             # Custom hooks atau local store fitur ini
│   │   ├── api/               # Query / mutation fetcher fitur ini
│   │   └── types/             # Skema tipe data TypeScript fitur ini
├── components/ui/             # Komponen primitif bersama (Button, Dialog, Input, Badge, Toast)
├── lib/                       # Utility murni (apiClient, formatRupiah, date)
└── styles/                    # Global token & Tailwind CSS
```

### 3.2 Triad State Management
1. **Server State:** Wajib dikelola oleh **TanStack Query** (React Query) atau **SWR**.
   * Menangani caching, deduplikasi query, revalidasi background, dan status error/loading otomatis.
   * Dilarang menyimpan data hasil fetch server di dalam global client store biasa.
2. **Global Client State:** Gunakan **Zustand** (< 1KB) jika benar-benar butuh membagi data antar halaman (misal: keranjang kasir, audio visualizer state). Hindari Redux yang over-boilerplate.
3. **Local UI State:** Cukup gunakan `useState` bawaan React untuk state lokal (toggle modal, dropdown).

### 3.3 Standar Form Handling & Validasi Mutlak
* Form wajib menggunakan pola deklaratif yang aman: **React Hook Form** dipadukan dengan skema validasi **Zod**.
* Pesan error wajib muncul langsung tepat di bawah field input yang bermasalah secara presisi.

### 3.4 Standar Aset & Unified Icon System (Flat Rounded Standard)
- **Wajib 1 Keluarga Icon Pack Resmi:**
  - Wajib menggunakan library resmi yang tree-shakable: **Lucide Icons** (`lucide-react` / `@lucide/lab`) atau **Phosphor Icons**.
  - Dilarang keras mengarang path SVG acak dari internet atau mencampur icon pack berbeda dalam satu proyek.
- **Geometri Flat-Rounded Mutlak:**
  - Semua ikon garis wajib memiliki atribut `stroke-linecap="round"` dan `stroke-linejoin="round"` untuk ujung dan sambungan sudut yang membulat halus.
  - Ketebalan garis (*stroke-width*) WAJIB seragam di seluruh aplikasi (standar: `1.5px` atau `1.75px`, viewBox `24x24`).
- **Larangan Mencampur Gaya (No Hybrid Chaos):**
  - Dilarang mencampur ikon bergaya outline dengan ikon bergaya fill/solid pada komponen sejajar, kecuali untuk indikator status aktif (misal: tab terpilih berubah jadi fill).
- **Ukuran Skala Proporsional (8pt Grid):**
  - Ikon mikro (tombol/badge): `14px` – `16px`.
  - Ikon navigasi/tabel: `18px` – `20px`.
  - Ikon fitur/empty-state: `24px` – `32px`.
- **Format Media:**
  - Gambar wajib menggunakan format modern (WebP/SVG) dan di-lazy-load.

### 3.5 Pola Cascade Layers & Runtime Token Derivation (The Platform-First Standard)
* **W3C Cascade Layers (`@layer`):**
  - Struktur CSS wajib didefinisikan dalam hierarki layer eksplisit untuk mencegah perang spesifisitas (*Zero `!important` rule*):
    ```css
    @layer reset, tokens, base, layout, components, utilities;
    ```
  - Aturan utilitas dan kustom selalu menang di atas gaya komponen secara alami tanpa hack spesifisitas selektor.
* **Token-Driven Runtime Derivation:**
  - Desain token wajib dipetakan ke CSS Custom Properties native (`--brand-primary`, `--brand-surface`).
  - Turunan warna (*hover*, *active*, *soft tint*, *border*) dihitung dinamis oleh browser via `color-mix(in srgb, var(--brand-primary) 15%, transparent)` tanpa perlu *rebuild step* atau dependensi runtime JavaScript.
* **Platform-First Micro-Architecture:**
  - Utamakan kapabilitas standar HTML5/CSS modern (seperti elemen native `<dialog>`, popover API, dan CSS grid/flexbox) sebelum menginstal library JavaScript pihak ketiga yang berat.

## ⚙️ MODUL 4: ARSITEKTUR BACKEND, STREAMING & REAL-TIME

### 4.1 Standar Python FastAPI (Python 3.11+)
* **Struktur Modular:**
  ```text
  backend/
  ├── app/
  │   ├── routers/       # Endpoint HTTP (APIRouter)
  │   ├── schemas/       # Skema Pydantic v2 (Input & Output validation)
  │   ├── models/        # Model database (SQLAlchemy 2.0 / SQLModel)
  │   ├── services/      # Logika bisnis murni
  │   └── core/          # Konfigurasi config, security, database session
  └── main.py            # Entry point
  ```
* **Asynchronous Wajib:** Gunakan `async def` pada setiap endpoint yang melakukan I/O database atau pemanggilan API eksternal.
* **Strict Typing:** Dilarang menggunakan `dict` polos tanpa skema. Semua request dan response wajib divalidasi oleh model **Pydantic v2**.

### 4.2 Protokol Real-Time & AI Streaming
* **Server-Sent Events (SSE):** Wajib digunakan untuk streaming respons teks AI (LLM generation per kata) dan notifikasi status pesanan satu arah (Kitchen Display). Jauh lebih ringan dan ramah firewall dibanding WebSocket.
* **WebSockets:** Gunakan jika dan hanya jika butuh komunikasi dua arah berkecepatan tinggi dengan data biner (seperti streaming potongan audio pada AI Meeting Recorder).

### 4.3 Background Processing
* Operasi berat (memproses file audio, generate dokumen PDF/Excel, kirim email) DILARANG menahan request HTTP.
* Jalankan di background menggunakan `BackgroundTasks` bawaan FastAPI atau serverless queue (Inngest / QStash) agar response HTTP tetap instan (< 150ms).

### 4.4 Status Code HTTP Semantik
* `200 OK`: Sukses ambil / update data.
* `201 Created`: Sukses membuat resource baru.
* `204 No Content`: Sukses menghapus resource.
* `400 Bad Request`: Parameter bisnis tidak sah.
* `401 Unauthorized`: Belum terautentikasi (belum login).
* `403 Forbidden`: Terautentikasi tetapi tidak memiliki hak akses (RBAC).
* `404 Not Found`: Data tidak ditemukan.
* `422 Unprocessable Entity`: Validasi skema input Pydantic gagal.
* `500 Internal Server Error`: Kegagalan server yang tidak terduga.

## 🗄️ MODUL 5: DATABASE, SKALABILITAS & SIKLUS DATA (Tahan 3 Juta Baris)

### 5.1 Indexing Mandatory Checklist
Sebelum mengeksekusi migrasi skema tabel apapun:
* [x] Setiap **Foreign Key** wajib memiliki index (contoh: `order_id`, `user_id`, `category_id`).
* [x] Setiap kolom pencarian, filter, dan sorting wajib memiliki index (`created_at`, `status`, `slug`, `invoice_no`).
* [x] Gunakan Composite Index untuk kombinasi filter yang selalu dipanggil bersamaan (`tenant_id` + `status`).

### 5.2 Standar Waktu & Timezone Mutlak (UTC Rule)
* **Aturan Mutlak:** Semua timestamp di database (`created_at`, `updated_at`, `expires_at`) WAJIB disimpan dalam format **UTC dengan timezone (ISO 8601 / `TIMESTAMPTZ`)**.
* Konversi ke waktu lokal pengguna (WIB, WITA, WIT) HANYA boleh dilakukan di layer tampilan frontend menggunakan `Intl.DateTimeFormat`.

### 5.3 Kebijakan Soft Delete (Data Audit Protection)
* Data krusial seperti transaksi keuangan, struk kasir, data pelanggan, dan invoice **DILARANG KERAS DI-HARD DELETE** (`DELETE FROM table`).
* Wajib menggunakan kolom `deleted_at TIMESTAMPTZ NULL` (*Soft Delete*) agar data historis tetap aman dan dapat diaudit.

### 5.4 Eliminasi N+1 Query & Pagination Wajib
* Dilarang melakukan query relasi di dalam perulangan loop. Wajib gunakan Eager Loading (`selectinload` di SQLAlchemy / SQL JOIN).
* Dilarang menjalankan query `SELECT *` tanpa batas. Setiap endpoint list data wajib menerapkan pagination berbasis cursor (`WHERE id < :cursor ORDER BY id DESC LIMIT 25`) agar query tetap < 5ms meski ada 3 juta baris.

### 5.5 Integritas Transaksi ACID
Operasi multi-tabel wajib dibungkus dalam Database Transaction: jika salah satu langkah gagal, seluruh operasi wajib dibatalkan (*automatic rollback*).

### 5.6 Manajemen Migrasi Skema
* Dilarang memodifikasi tabel database produksi secara manual.
* Wajib menggunakan migration tool resmi: **Alembic** untuk Python atau **Drizzle Kit** untuk TypeScript.

## 🔒 MODUL 6: KEAMANAN ZERO-TRUST & OTENTIKASI

### 6.1 Manajemen Sesi Aman (Anti-XSS Cookie Standard)
* ❌ **DILARANG KERAS** menyimpan token otentikasi (JWT) di `localStorage` atau `sessionStorage` browser (rentan dicuri lewat script jahat XSS).
* ✅ **Wajib:** Simpan token di dalam **HTTP-Only, Secure, SameSite=Lax (atau Strict) Cookie** yang tidak dapat diakses oleh JavaScript browser.

### 6.2 Kebijakan CORS & Rate Limiting
* Backend wajib mengonfigurasi **CORS Whitelist** ketat (hanya domain frontend resmi yang diizinkan mengakses API).
* Terapkan **Rate Limiting** pada endpoint publik (terutama `/auth/login`, `/register`, dan endpoint AI) untuk mencegah serangan brute force dan pengurasan kuota token.

### 6.3 Isolasi Variabel Lingkungan (Env Secrets)
* Bedakan variabel publik (misal: `NEXT_PUBLIC_API_URL`) dan variabel rahasia server (database credentials, private AI API key).
* Dilarang keras mengekspos secret key ke dalam file client bundle.

### 6.4 Sanitasi Input & Parameterized Queries
* Semua input teks disanitasi untuk mencegah XSS.
* Akses database wajib menggunakan *parameterized queries* / ORM untuk mencegah SQL Injection.

## ☁️ MODUL 7: DEPLOYMENT RESILIENT & FREE-TIER ARCHITECTURE (RP 0)

### 7.1 Bebas Cold Start
* Hindari hosting gratisan yang menerapkan *idle spin-down* (seperti Render Free Web Service yang butuh 50 detik untuk bangun).
* Utamakan Serverless / Edge Platform: **Vercel**, **Cloudflare Pages / Workers**, atau **Supabase**.

### 7.2 Stateless Backend & Cloud Storage
* Backend dirancang 100% stateless (tidak menyimpan file atau memori session di server lokal).
* Seluruh upload file (foto menu, dokumen, rekaman audio) dialirkan ke Cloud Object Storage gratis (Supabase Storage / Cloudflare R2 / AWS S3 free tier).

### 7.3 Edge Caching & Database Connection Pooling
* Aset statis di-cache di Edge CDN dengan header `Cache-Control` immutable agar TTFB (Time to First Byte) < 100ms di seluruh Indonesia.
* Database serverless wajib menggunakan **Connection Pooler** (misal Supabase port 6543 / PgBouncer) agar koneksi tidak habis saat traffic melonjak.

## 📦 MODUL 8: WORKFLOW HYGIENE, VERIFIKASI & GIT STANDARD (10/10 PERFECTION)

### 8.1 Protokol `.env.example` Otomatis (Zero-Leak & Zero-Confusion)
* Setiap kali ada penambahan atau perubahan variabel lingkungan (`.env`), agen **WAJIB otomatis membuat/memperbarui file `.env.example`**.
* File `.env.example` berisi nama key dengan nilai dummy/placeholder yang aman dan 1 baris komentar dokumentasi singkat.
* Dilarang keras menyertakan nilai secret/password asli ke dalam `.env.example` atau ke dalam commit Git.

### 8.2 Self-Verification Smoke Test Sebelum Lapor Selesai
* Sebelum agen menyatakan *"fitur telah selesai"* atau meminta user mencoba di browser, agen **WAJIB menjalankan self-verification internal**:
  * Memastikan tidak ada *broken import* atau file yang lupa diekspor.
  * Memastikan tidak ada sintaks fatal yang menyebabkan *white screen of death*.
  * Jika ada error fatal, agen wajib memperbaikinya secara mandiri sebelum melapor ke pengguna.

### 8.3 Semantic Conventional Commits
* Seluruh pencatatan riwayat commit Git wajib menggunakan format standar industri:
  * `feat: [nama fitur baru dalam bahasa manusiawi]`
  * `fix: [perbaikan bug spesifik]`
  * `refactor: [pemecahan modul / restrukturisasi kode tanpa ubah fungsi]`
  * `perf: [optimasi kecepatan / caching / memory]`
  * `chore: [update config / env / dependencies]`
* Dilarang membuat pesan commit malas atau generik seperti *"update"*, *"fix"*, atau *"commit"*.
